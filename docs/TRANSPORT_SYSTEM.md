# 虚空传输体系实现说明

> 更新时间：2026-07-19  
> 目标：Minecraft 26.2 / NeoForge 26.2.0.7-beta / Temple of Nihility 1.0.0-beta.3

## 玩家闭环

1. 将虚空传输核心放在输入容器和输出容器之间。
2. 右键核心打开原版发射器布局的配置界面。
3. 设置唯一输入面、唯一输出面和资源模式。
4. 综合模式选择轮换或物品/流体/能量优先。
5. 需要物品筛选时，把物品拿在鼠标上左键九格幽灵筛选槽；右键槽位清除。
6. 选择关闭、白名单或黑名单，并按需设置红石条件。
7. 顶部状态直接显示运行、空输入、筛选拒绝、接口缺失、区块未加载或输出阻塞；悬停显示路线与上一轮吞吐。

## 服务端真值

- 方块实体持久化输入方向、输出方向、资源模式、综合优先级、红石模式、筛选模式和九格幽灵样本。
- 客户端只通过容器按钮和槽位点击提交意图；真实配置、搬运与诊断都由服务端菜单和方块实体结算。
- 输入和输出不能相同；定向模式不会在失败时偷偷反向搬运。
- 综合模式每轮只搬运一种资源。轮换优先级按物品、流体、能量循环起点；固定优先级会在首选资源不可搬运时继续尝试后续资源。
- 物品筛选比较物品及数据组件。白名单为空时拒绝物品，黑名单为空时允许全部物品。
- 搬运使用 NeoForge 26.2 `ResourceHandlerUtil`、`EnergyHandlerUtil` 和事务语义，不通过原版命令或聊天文本执行。

## 性能与配置

- 默认每 20 tick 检查一次，只检查一个输入位置和一个输出位置，不扫描世界或网络。
- 默认每轮上限：16 个物品、250 mB 流体或 256 NeoForge 能量。
- `transport.interval_ticks`、`items_per_operation`、`fluid_per_operation` 和 `energy_per_operation` 均可在 common 配置中调整并有安全上下限。
- 在读取能力前检查相邻区块是否已加载，传输核心不会为了轮询主动加载区块。

## 存档迁移

- 新放置核心默认使用北输入、南输出、综合轮换、忽略红石、关闭筛选。
- 缺少 `TransportConfigVersion` 的旧核心继续使用旧三轴双向回退逻辑，避免已有装置在升级后静默改流向。
- 玩家修改任一方向、模式、优先级、红石或筛选设置后，旧核心写入版本 1 并迁移为新单向路由。

## 自动验证

- `TransportPolicyTest` 的 7 个用例覆盖方向互斥、红石规则、综合轮换、固定优先级、空白名单/黑名单、诊断优先级和损坏持久化 id 回退。
- `NihilityTransportLayoutTest` 的 3 个用例锁定左右按钮、九格筛选、清空按钮和玩家背包的边界，防止后续界面改动重新发生遮挡。
- 构建门禁继续检查全部资源 JSON、双语键一致性和正常玩法无命令路由。
- 尚待玩家运行时验证：真实容器组合、流体模组容器、多个核心竞争、旧存档迁移、低 TPS 和小窗口 GUI。
