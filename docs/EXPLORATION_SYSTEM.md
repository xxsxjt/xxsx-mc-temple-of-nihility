# 神龛、圣殿群与居民探索切片

> 目标版本：Minecraft 26.2 / NeoForge 26.2.0.7-beta  
> 当前范围：神龛、中型圣殿、圣殿群代表结构、和平开局路线、居民状态同步和首批行为差异

## 玩家入口

玩家在主世界发现神龛后，可以从开放入口直接识别中心归零祭坛。神龛自带四向符文砖，中心祭坛已经达到 I 级；四角灯柱负责远距离识别，东侧供物匣提供少量归尘、空寂石和概率奖励。

供物匣属于圣殿居民看守的容器。开启后，附近居民会先以姿态和流光进入短暂警戒，再开始反击；聊天栏会只提示一次。玩家不需要开启供物匣才能进入主线。

## 和平开局

空寂石现在可在熔炉中烧成归尘。玩家采集八块空寂石并熔炼后，可在任意归零祭坛执行 `8 归尘 -> 1 虚无残片`，因此第一枚交易/制作货币不再要求击杀中立居民。

该路线和居民掉落是并列选择：

- 和平路线：采集结构石材 -> 熔炼归尘 -> 归零仪式。
- 风险路线：开启供物匣 -> 取得早期材料 -> 应对居民警戒。
- 战斗路线：主动攻击居民 -> 附近同类结队反击 -> 获得额外阶位掉落。

## 中型圣殿

中型圣殿不再是空墙盒，当前分成四个连续区域：

- 南侧入口通道：追随者守卫固定出生，不再随机刷进墙体。
- 西侧交易厅：信众承担和平交易入口，地面和灯柱与其他房间区分。
- 东侧供物档案厅：独立补给匣保证归尘和残片，并有概率提供结晶或《虚无圣典》；开启会触发居民警戒。
- 北侧 II 级仪式厅：后部祭坛自带四向符文与四角水晶，由追随者和令使守卫。

`TempleLayoutPolicy` 是房间、门洞和地板角色的单一坐标规则；测试固定南门宽高、侧厅门、仪式厅中央门和五类地板分区。

## 圣殿群

圣殿群不再使用封闭实心塔，而是由开放地形上的五段路线组成：

- 南侧三格宽入口：由随行者守望，直接通向中央圣所。
- 中央 III 级圣所：中心归零祭坛自带符文、四角结晶、外圈柱基和灯柱，由大令使驻守。
- 西侧宝库厅：生成一座未认领宝库作为设施样例，由令使守卫；玩家首次合法使用时可按现有宝库规则认领。
- 东侧能量传输厅：并列展示汲能棱柱、传输核心和能量容器，让玩家在结构中看到三种设施的空间关系。
- 北侧守护庭院：放置独立遗物匣，可能提供结晶、遗物残片或虚无核心；圣者保持中立驻守，不强制触发首领战。

四个房间和中央圣所通过三格宽门洞与连接带贯通，未使用的四角保留为开放地形。遗物匣属于看守容器，开启后沿用统一的居民警戒与结队反击规则。

`TempleComplexLayoutPolicy` 是圣殿群房间、连接带、边墙和门洞的单一坐标规则；纯逻辑测试固定五类区域、开放角落及全部三格门洞。

## 居民状态

居民状态由服务端写入同步实体数据，客户端模型、流光和交易可用性读取同一状态：

| 状态 | 行为 | 玩家反馈 |
|---|---|---|
| 平静 | 中立游荡，可接近 | 常态姿态与低强度流光 |
| 交易 | 绑定一个实际交易玩家 | 收拢双臂；第二位玩家收到“正在交易”提示 |
| 警戒 | 容器开启或受击后的短暂前摇 | 抬臂、暖白警戒流光；交易立即关闭 |
| 敌对 | 追击当前目标 | 前倾攻击姿态、更强的流光与粒子 |
| 仪式挑战 | 圣者接受 III 级祭坛请战 | 展开双臂、增强灰白流光并显示挑战边界；只与请战者交战 |

同一目标的重复交互不会重复启动警戒或刷屏。约 30 秒后失去有效目标的居民恢复平静。交易冷却写入实体存档，不再靠卸载实体重置。

## 阶位差异

- 虚无信众：玩家平静状态下冲刺逼近时会主动退开，但正常步行仍可交易。
- 随行者：中距离前摇拦截；6 格内低阶友军生命不高于一半且即将被投射物命中时，可吸收一次投射物，冷却 12 秒。
- 令使：近身物理折返；每 6 秒可反射一次敌方投射物；中距离使用 12 tick 裂界指向，只把目标移到合法侧方空位。
- 大令使：中距离展开禁域，限制冲刺并提高传送能量成本；可一次性召回最多三名参战低阶友军，低生命时生成三节点减伤护盾。
- 圣者：通过 III 级祭坛主动请战，具备宣告、边界、唯一参与者、退出恢复和独立奖励；战斗中交替使用可横向躲避的抹除线与持续推离的缺失区域。
- 所有阶位：受击会按阶位范围召集附近居民；创造和旁观玩家不会成为合法目标。

圣者首批两项专属招式已接线，但轨迹可读性、伤害结算、区域推离、受击打断和多人隔离仍待运行时复测。随行者与令使的事件取消、反射后投射物归属和裂界落点，以及大令使的范围扫描、传送成本、召回落点和护盾结算也未运行时验证。不得把源码接线描述成五套已完成运行时验收的战斗 AI。

## 权威实现

- `CreatureDispositionPolicy`：状态优先级、警戒前摇、守区和召集半径。
- `NihilityCreature`：服务端状态、交易占用、警戒计时、结队反击和冷却存档。
- `NihilityBeliever`：冲刺接近退避 Goal。
- `CreatureActionPolicy` / `CreatureActionLockGoal`：动作阶段、冷却和 AI 控制锁。
- `CreatureProjectileDefensePolicy` / `CreatureProjectileDefenseService`：护卫与偏转的低生命、阶位、冷却、友方和命中事件规则。
- `NihilityFollower` / `NihilityEnvoy`：拦截、投射物护卫、近身折返、投射物偏转和裂界指向状态。
- `SaintChallengePolicy` / `SaintChallengeService`：III 级祭坛请战条件、唯一参与者、边界、超时、退出和恢复。
- `SaintActionPolicy`：圣者招式轮换、抹除线走廊和缺失区域半径的纯逻辑规则。
- `NihilitySaint`：挑战阶段同步、参与者隔离、存档、奖励、招式锁定、区域生命周期和卸载后恢复。
- `TempleGenerator`：三种结构布局、三套结构战利品、角色出生点、守区和持久化。
- `TempleLayoutPolicy`：中型圣殿的入口、分区、门洞与外墙规则。
- `TempleComplexLayoutPolicy`：圣殿群的圣所、两翼、北庭、连接带和门洞规则。
- `NihilityCreatureRenderer` / 模型 /流光层：从同步状态生成可见姿态。
