# 四系设计准则

本模组现在把历史上的 `nihility_*` 注册名视为兼容性前缀，不再把所有内容都硬叫“虚无”。玩家可见名称、提示、贴图、粒子、功能、配方应按下面四系分工处理。

## 虚无

- 核心概念：真正的什么都没有、归零、删除、抹除，连“虚空空间”这种容器都不存在；这里不是“无相”，也不是带佛家味道的空性。
- 视觉语言：黑白灰、硬质缺口、被删除的边缘、极少量冷色边光、少而干净的动态；重点是“缺失”和“不存在”，不是空灵、禅意或佛家空性。
- 功能语言：遁入虚无、融于虚无、归零净化、伤害闪避、虚无能量、自动修复。
- 避免：紫色混沌、星空空间、深渊生物、莲花/禅意/佛家空无感、无相概念混用、只套原版药水却写成高概念效果。

## 虚空

- 核心概念：空间、界域、距离折叠、仓储、传送、引力、裂隙。
- 视觉语言：深青、透明边界、空间裂缝、稀疏星点、宝库连接面。
- 功能语言：虚空宝库、虚空终端、传送石、磁吸、引力场、物流/传输。
- 避免：把虚空说成真正虚无；虚空是下位的空间属性，更偏实用设施。

## 混沌

- 核心概念：无序增幅、随机、暴走、扰动。
- 视觉语言：紫色、流动彩辉、不稳定辉光、高动态颜色。
- 功能语言：幸运扰动、战斗增幅、共鸣核心、高风险强化、商旅印。
- 避免：把混沌的紫色视觉套到虚无工具/护甲上，除非该物品明确是混沌系。

## 深渊

- 核心概念：西幻魔性、灵魂、诅咒、复苏、深渊战意。
- 视觉语言：暗红、冷色魂火、骨纹/咒纹、更重的哥特轮廓；紫色只作极少阴影，不与混沌主色争夺识别。
- 功能语言：复苏、虹吸、魂锚、战号、战鼓、深渊生物和交易。
- 避免：把深渊厚重魔法感混进干净的虚无装备。

## 当前归类

- 虚无：工具、护甲、归零卷轴、净业铃、屏障核、守护印、相位/遁入类物品。
- 虚空：虚空宝库、虚空终端、传送石、磁核、引力符、停滞表、传输核心。
- 混沌：混沌血戒、幸运符、手甲、王冠、共鸣核、商旅印。
- 深渊：复苏宝珠、战号、魂瓶、魂锚、披肩、虹吸戒、深渊生物。

新增内容时先选属性，再让功能和贴图共同证明这个属性。若效果目前只是原版增益，就不要用过度文案包装成旗舰能力；要么诚实写清，要么补实现。

## 界面身份

- 虚无仪式：使用断裂、缺位、留白和非连续引导线表达归零，不使用现代机器进度条或通用紫色面板。
- 虚空设施：沿用 Minecraft 容器的槽位和操作习惯，突出网络、容量、方向、距离和连接状态。
- 混沌设备：重点是可预览的扰动和动态变化，不能只把普通机器面板染紫。
- 深渊交互：使用契约、灵魂和哥特器物语言；交易界面应像与生物订立契约，而不是另一台仓储机器。
- 不同方块即使共享底层菜单代码，也必须有不同的信息层级、操作流程和视觉地标，不能只换标题与颜色。

## 模组图标

- 当前 `logo.png` 为 256x256 图标，2026-07-19 通过 image2 工作流生成；高分辨率母版保留在本地 `_image2_raw/`，不进入发行 jar。
- 主轮廓是被精确抹除的透明圣殿门，中央负形代表不存在本身；材质使用无色玻璃、清水流纹、珍珠白边缘和极少冷青高光。
- 图标必须在 32x32 至 64x64 缩略尺寸仍能识别圣殿门与中央缺失，禁止重新引入紫色晶体、星空、混沌光环、深渊或手游徽章式外框。
- `META-INF/neoforge.mods.toml` 使用 `logoFile="logo.png"`，构建后必须确认根目录图标进入 jar。
