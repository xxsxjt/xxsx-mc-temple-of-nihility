# 虚无圣殿现状审计与下一阶段计划

> 审计日期：2026-07-19  
> 目标版本：Minecraft 26.2 / NeoForge 26.2.0.7-beta  
> 当前模组版本：1.0.0-beta.3  
> 范围：仅审查 `Temple of Nihility`，不处理测试实例中其他模组的问题。

本文是当前开发阶段的实现真值表和执行计划。结论来自注册表、配方、世界生成 JSON、掉落表、事件、菜单、兼容层、资源联系表、构建产物和现有日志；路线图或物品文案本身不算实现证据。

## 一、当前基线

- 63 个独立物品注册、15 个方块、5 类生物、3 个自定义效果、4 个菜单、97 个配方、23 个掉落表、135 张 PNG 资源。
- 2026-07-19 完成完整 `clean build`，包含 74 个纯逻辑回归测试、玩法命令路由门禁、全部资源 JSON 解析、仪式与探索定义校验和 481 组中英文键一致性检查；最终 jar 为 `temple-of-nihility-neoforge-26.2-1.0.0-beta.3.jar`，SHA256 `D659E50CED9A03D3DFD0F6026282ED434631894D96A7A718110B021B5FCB4FE9`。
- 最终 jar 已部署到 NeoForge 26.2 测试实例，源文件与部署文件哈希一致；实例顶层只保留一个有效 Temple jar，旧包移入 `disabled-templenihility/deploy-20260719-210841`。
- 宝库聚合存取现在使用先规划后提交的事务：限制合法单组取出，阻止数字键复制和满仓点击反向取物，批量常加载/保护设置失败时回滚，失效网络会关闭菜单。
- 相位能力恢复已抽成可测试状态解析器，覆盖生存、外部飞行、非飞行 mayfly、旁观和原版隐身保留。
- 终端打开动作增加服务端 5 tick 去抖并在退出时清理，搜索 payload 保持 64 字符解码上限；武器动作继续由 ACTIVE、冷却和能量三重验证防止重复启动。
- 独立服务端已在 Curios 存在时加载至 `Done`，证明指导书公共类不会错误加载客户端 Screen；这不能代替客户端逐页、GUI、结构、动作和联动验证。
- 日志中的 Sodium Extra 访问转换器、Create 类缺失、Mojang 401 和客户端关闭看门狗问题不属于本模组，本计划不处理。

## 三、当前最高优先级问题

### P0：先让玩家能学会并完成现有玩法

1. **最新 beta.3 客户端验收仍不完整**：构建、资源和独立服务端启动通过，但指导书逐页布局、GUI、结构、动作和联动仍需实际客户端复核。
2. **和平入口已接线、仍待复测**：空寂石熔炼归尘和初级归零仪式已解除强制击杀，但必须确认自然神龛、熔炼、供物匣和居民警戒在新世界真实工作。
3. **路线图需要持续同步**：棱柱、传输和指导书状态已经修正；后续行为改动必须同批更新圣典、JEI、提示和文档。

### P1：闭合已经做出来的系统

1. 生物已有五态、随行者拦截/护卫、令使近身折返/偏转/裂界指向、大令使三项机制，以及圣者请战、抹除线和缺失区域；下一步先做全动作运行时回归，再扩圣者低生命阶段。
2. 按 [ITEM_MECHANICS_AUDIT.md](ITEM_MECHANICS_AUDIT.md) 逐件做运行时回归；源码真实性整改已完成第一轮，不能再只凭工具提示判断完成。
3. 传输核心的面向、过滤、综合优先级、红石模式和阻塞信息已接线；下一步必须完成真实物品/流体/能量组合和旧存档运行时复测。
4. 祭坛数据配方和统一客户端来源已完成；下一步扩四系时补催化物、阶段、中断回滚和风险预览，避免退化为换色线性升级链。
5. 武器动作需要客户端同步与第三人称姿态，否则服务端逻辑有了但玩家看不懂前摇和生效窗口。

### P2：重做世界内容和统一表现

1. 三种结构代表切片和圣者可选仪式挑战均已接线；下一步是新区域运行时验证、挑战场景细节、地形适配和窄范围结构变体。
2. 先建立四系代表资产参考板，再按属性分批重绘；禁止整批使用同一提示词换颜色。
3. 祭坛使用灰白断裂和缺失表达虚无；交易使用暗红、魂火和契约表达深渊；终端保持克制的原版仓储工具风格。
4. 删除未注册的旧 `ModWorldEvents` 生成草案等死代码，减少后续误判和重复维护。

## 四、下一阶段执行顺序

在下列阶段完成前，不新增另一批散装物品。

### 阶段 A：实现《虚无圣典》 `[~]`

使用 NeoForge 26.2 已核对的原版 `BookViewScreen`，不再手绘仿制书本 GUI。指导书可重复使用，不消耗。

合成与发现：

- 配方：一本原版书 + `templenihility:guide_materials` 标签中的任意一种最低阶材料。
- 标签首批包含：空寂石、虚无残片、归尘。空寂石保证玩家找到圣殿后不必先攻击中立生物。
- 指导书放在创造标签页前部，并增加配方发现或一次性克制提示；安装 JEI 时增加物品信息。
- 公共物品类不直接链接客户端 Screen；使用现有项目认可的受保护客户端桥或服务端到客户端载荷，并做专服启动测试。

页序以玩家决策为主，不做物品目录：

1. 从这里开始：本模组增加什么，前三步做什么。
2. 游玩路线：发现圣殿 -> 获取首批材料 -> 使用祭坛 -> 建立宝库与能量 -> 高阶交易与装备。
3. 圣殿在哪里：主世界生物群系、三种规模、约略间距、`/locate structure templenihility:nihility_temple`。
4. 第一批材料：挖取路线、掉落路线和安全替代路线。
5. 归零祭坛用途和等级。
6. I 级俯视图：中心祭坛，四向紧邻圣殿符文砖。
7. II/III 级俯视图：四角水晶；两格外四向圣殿柱；外四角錾制空寂石。
8. 如何运行祭坛：放入、预览、能量、点击仪式、输出和失败信息。
9. 当前七条祭坛进阶链，只写已实现数量、等级和能量成本。
10. 五类生物与交易：中立现状、阶位、货币、掉落、冷却和商旅印。
11. 大令使：禁域、传送成本、召回和三节点护盾。
12. 圣者请战：III 级祭坛入口、边界、退出和奖励。
13. 随行者与令使：投射物护卫、偏转、近身折返和裂界指向。
14. 虚空宝库：连接、容量、同类聚合、终端绑定、搜索、排序、合成、保护和常加载。
15. 虚无能量：护甲、棱柱、容器、储能/传导饰品和主要消耗。
16. 武器动作与自定义虚无状态。
17. 可选联动：JEI、Waystones 和 Curios。
18. 常见失败症状和恢复动作。

验收：配方可从早期材料完成；每页在最小支持分辨率可读；祭坛图能按扫描器逐坐标复原；专服不加载客户端类；中英文页数一致。

当前进度：物品、标签配方、配方发现、JEI 信息、21 页双语内容和祭坛图已经实现；构建与独立服务端 `Done` 已通过。剩余客户端逐页布局、实际合成和右键打开验证。

## 五、完成定义

下一测试版必须同时满足：

- 玩家只靠《虚无圣典》和游戏内反馈即可完成第一次圣殿探索、一级祭坛、一次仪式和第一个宝库网络。
- 当前所有高概念物品的文案都能由代码证明，或已明确降级为真实效果描述。
- 最新 jar 完成构建、资源解析、专服启动、客户端小窗口、结构、菜单和联动测试。
- 测试实例只保留一个有效 Temple jar，部署物和构建物 SHA256 一致。
- 指南、JEI、README、工具提示、实际成本和当前版本号保持一致。
