## 三、本轮开发进展

### 实现"归零终式"（圣者低生命阶段招式）

这是路线图 P1 与 ACTION_SYSTEM.md 明确标记的 `[ ]` 未实现高优先级项。需求原文："归零终式：低生命阶段使用，多段安全区逐步缩小；安全区规律可读，不做全屏随机秒杀。"

**改动内容**：

1. **`action/SaintActionPolicy.java`** — 新增归零终式纯逻辑策略：
   - 低生命阈值 `LOW_HEALTH_FRACTION = 0.30`
   - 安全区从 12 格**线性收缩**到 2 格（`terminusSafeRadius(progress)`）
   - 区外伤害随收缩从 1.5 升至 6.0（`terminusDamage(progress)`）
   - 低生命时每 3 个动作周期插入一次归零终式（可读规律，非随机）

2. **`action/CreatureActionPolicy.java`** — 新增动作类型 `SAINT_VOID_TERMINUS`（14 前摇 / 300 冷却）

3. **`entity/NihilitySaint.java`** — 服务端真实执行：
   - `startVoidTerminus`：锁定以圣者为中心的安全区，玩家收到明确提示
   - `tickVoidTerminus`：安全区逐 tick 收缩脉冲，区外玩家按进度受伤害
   - 挑战结束/离开时清理状态

4. **`world/NihilityVisualEffects.java`** — 三个特效：前摇双环图、激活爆炸云、随半径收缩的脉冲环

5. **语言键** — 中英双语新增 `saint_void_terminus_start` 提示（"安全区不断缩小，请待在区内"）

6. **测试** — 新增 5 个 JUnit：低生命周期性触发、健康态不触发、安全区单调收缩、区外判定、伤害随收缩上升

**历史验证**：2026-08-09 已记录完整构建 **BUILD SUCCESSFUL**、**79 测试全过**（原 74 + 新 5），资源/语言/仪式门禁全通过。2026-09-14 的当前构建和 SHA256 见本报告下一步复核条目。

**备份**：改动前已备份到 `_backup_20260809_saint-terminal_fix/`（含 5 个改动源文件）。
